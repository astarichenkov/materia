# Lecture Editor, revision history и повторный экспорт

Day 35. Редактор позволяет довести автоматически обработанную лекцию до
качественного документа без повторного скачивания, FFmpeg и Whisper.

## Открытие

- Из библиотеки: `Открыть` → `Редактор`, либо сразу `Редактор`.
- Прямой адрес: `GET /lectures/{id}/editor`.
- API: `/api/lectures/{id}/editor`.

Страница работает только с артефактами одной лекции. Никакой ввод не задаёт
файловый путь: файлы адресуются только через allow-list артефактов лекции.

## Вкладки

| Вкладка | Что можно делать |
|---------|------------------|
| Оригинал | править текст сегментов; таймкоды, порядок и медиа не меняются |
| Перевод | видеть EN+RU, править RU, фильтровать WARNING/вручную/устаревшие, отмечать «Проверено», повторять перевод сегмента |
| Конспект | редактировать Markdown, безопасный предпросмотр, пересоздать конспект из перевода |
| Слайды | просмотр уже извлечённых слайдов с таймкодами (повторное извлечение не запускается) |
| История изменений | список ревизий, сравнение двух версий, восстановление версии |

## Ревизии и блокировка

- Каждая правка создаёт новую неизменяемую ревизию (`lecture_document_revision`):
  номер, контент, SHA-256, родительская ревизия, источник
  (`WHISPER`/`TRANSLATION_LLM`/`TEXT_PROCESSING_LLM`/`HUMAN`/`AI_ASSISTED`).
- Исходная ревизия каждого документа не удаляется при очистке старых версий.
- Перед сохранением клиент присылает `expectedRevision`. Если документ уже
  изменён в другой вкладке — сервер отвечает `409 REVISION_CONFLICT`, данные не
  перезаписываются.
- `transcript.json` (сырой выход Whisper) не перезаписывается редактором.
- Лимиты: `app.editor.max-segment-chars` (8000), `max-notes-chars` (400000),
  `max-batch-segments` (500).
- Сохранение **никогда** не удаляет историю. Очистка старых ревизий — только
  явный запрос `POST .../revisions/prune?type=...&keep=...`; исходная ревизия
  сохраняется всегда, `keep` ограничен `app.editor.max-revisions-per-document`.

## Устаревание зависимых документов

| Действие | Последствия |
|----------|-------------|
| правка оригинала | изменённые сегменты перевода → `STALE`; конспект → `STALE`; чекпоинты `TEXT_PROCESSING`+`EXPORT` инвалидируются, Whisper сохраняется |
| правка перевода | конспект → `STALE`; `TEXT_PROCESSING`+`EXPORT` инвалидируются |
| правка конспекта | `EXPORT` инвалидируется; `notes.json` обновляется, чтобы последующая обработка не откатила правку |
| повторный экспорт | ничего в пайплайне не запускает |

`STALE`-перевод не считается актуальным: в экспорт он не попадает как текущий
перевод (используется исходный текст), а в интерфейсе показывается отдельным
статусом. Точечная правка оригинала не инвалидирует весь перевод — только
затронутые сегменты.

## Приоритет человека

- Ручная правка перевода получает статус `MANUALLY_CORRECTED`, проверенная —
  `REVIEWED`. Обе считаются «done» и **не перезаписываются** автоматическим
  переводом/повторным запуском.
- «Пересоздать конспект» и принятие варианта повторного перевода создают новую
  ревизию (`AI_ASSISTED`); предыдущая человеческая ревизия остаётся в истории.

## Повторный перевод сегмента

1. Кнопка «Повторить перевод» у сегмента.
2. Сервер использует задачу `LECTURE_TRANSLATION` (тот же провайдер/модель, что
   и обычный перевод), соседние сегменты как контекст и глоссарий.
3. Возвращается **предложение**, ничего не сохраняется автоматически. Если
   сегмент уже правился вручную, интерфейс предупреждает об этом.
4. «Принять вариант» сохраняет новую ревизию. Проверка качества (кириллица,
   числа, термины, длина) применяется и к предложению.

### Облачный повтор и приватность

Повтор через облако по умолчанию запрещён. Нужны **два** условия:

- `app.editor.allow-cloud-retry=true` (`EDITOR_ALLOW_CLOUD_RETRY`);
- пользователь включил «Разрешить облачный повтор перевода WARNING-сегментов»
  в редакторе (хранится в `app_setting` → `editor.allow-cloud-retry`).

При включённом флаге приватный текст лекции может уйти в облако — это осознанное
решение пользователя, а не поведение по умолчанию.

## Безопасность

- CSRF: заголовок `X-Editor-Csrf` (или `_csrf`) для всех изменяющих запросов.
- Каждый запрос проверяет существование лекции; IDOR ограничен рамками
  установки (как и остальные данные приложения).
- Markdown-предпросмотр рендерится на сервере: вход экранируется, сырой HTML не
  проходит, ссылки/изображения — только абсолютные `http(s)`.
- Размеры текста ограничены на сервере; пути файлов из запроса не принимаются.
- Скачивание — только allow-list имён артефактов лекции.

## API

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/lectures/{id}/editor` | view: сегменты, перевод, конспект, слайды, quality, ревизии, экспорты |
| POST | `.../transcript` | сохранить правки оригинала |
| POST | `.../translation` | сохранить правки перевода (пакетно) |
| POST | `.../translation/segments/{seq}/review` | отметить сегмент проверенным |
| POST | `.../translation/segments/{seq}/retry` | предложение повторного перевода |
| POST | `.../translation/segments/{seq}/accept` | принять предложение |
| POST | `.../notes` | сохранить Markdown |
| POST | `.../notes/regenerate` | пересоздать конспект из перевода (без Whisper) |
| POST | `.../notes/preview` | безопасный HTML-предпросмотр |
| GET | `.../revisions?type=` | история ревизий |
| GET | `.../revisions/{revId}?type=` | одна ревизия |
| POST | `.../revisions/{revId}/restore?type=` | восстановить версию (как новую) |
| GET | `.../compare?type=&from=&to=` | построчный diff |
| POST | `.../export` | `{"variant":"ORIGINAL\|RUSSIAN\|BILINGUAL\|NOTES"}` |
| GET | `.../exports` | журнал экспортов |
| PUT | `.../settings/cloud-retry` | `{"enabled":true\|false}` |
| POST | `.../revisions/prune?type=&keep=` | явная очистка старых ревизий |

## Экспорт без Whisper

```
revision → load content → existing slides → Markdown + DOCX
         → atomic replace → lecture_export row (source revision ids + hash)
```

- Варианты: `notes.original.docx`, `notes.ru.docx`, `notes.bilingual.docx`,
  `notes.docx` (+ соответствующие Markdown).
- Экспорт не вызывает download/FFmpeg/Whisper/translation/text-processing.
- DOCX пишется во временный файл и атомарно заменяет старый; при ошибке
  предыдущий документ остаётся доступным.
- Слайды берутся из `slide` (повторно не извлекаются). Отсутствующие на диске
  файлы пропускаются с предупреждением; в DOCX они не ломают экспорт.
- В `lecture_export` сохраняются id исходных ревизий и хеш, поэтому UI показывает
  «устарел», если документ изменился после последнего экспорта.

## Библиотека

`GET /` поддерживает `q` (название/тема), `language`, `status`,
`hasTranslation`, `sort=date-desc|date-asc|title`. Используются существующие
таблицы лекций, `lecture_topic` и перевода — второй поиск не создаётся.

## Диагностика

`GET /diagnostics` (и `GET /api/diagnostics`) проверяет Java, каталог данных и
свободное место, temp, SQLite, FFmpeg/FFprobe, Whisper+модель, yt-dlp и Ollama
(включая наличие моделей). Каждая проверка содержит статус и подсказку.
