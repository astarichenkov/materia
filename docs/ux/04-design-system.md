# UX-4. Дизайн-система для Thymeleaf + HTMX

Спецификация минимальной, но достаточной дизайн-системы. Код компонентов на
этом этапе не пишется; документ задаёт контракт для следующего задания.

---

## 1. Визуальные принципы

1. **Спокойная рабочая среда.** Нейтральный фон, один акцентный цвет, цвет
   только для статуса/действия.
2. **Текст важнее хрома.** Основной контент — транскрипция, перевод, конспект;
   интерфейс не должен с ними конкурировать.
3. **Плотно, но читаемо.** Это инструмент, а не лендинг: 14–16 px base,
   умеренные отступы, таблицы/списки с ясными заголовками.
4. **Один primary action.** На экране одна заливная кнопка; остальные —
   secondary/ghost/danger.
5. **Состояние всегда видно.** Loading, empty, error, partial, disabled —
   отдельные компоненты, а не «просто текст».
6. **Технические детали — по запросу.** ID, токены, этапы, провайдеры,
   модели, MCP — в «Детали»/админ-режиме.

## 2. Сетка и layout

### Desktop (≥ 1024 px)

```
┌─────────────────────────────────────────────────────────────────────┐
│ Topbar 64 px: logo | breadcrumb | [Добавить материал] | admin menu  │
├──────────────┬──────────────────────────────────────────────────────┤
│ Sidebar      │ Content                                              │
│ 240 px       │ max-width 1200–1280 px, padding 32 px                │
│ sticky       │                                                      │
└──────────────┴──────────────────────────────────────────────────────┘
```

- 12-колоночная сетка, gutter 24 px.
- Контент: max-width 1280 px, на широких экранах — центрирование.
- Sidebar: 240 px, сворачивается до 64 px (иконки) на 1024–1200 px.
- Topbar: 64 px, sticky.

### Tablet (640–1023 px)

- Sidebar → drawer, topbar с гамбургером.
- Контент: padding 24 px, одна колонка, карточки 2 в ряд, где уместно.

### Mobile (< 640 px)

- Одна колонка, padding 16 px.
- Topbar 56 px: меню, заголовок, «Добавить».
- Таблицы: либо карточки, либо горизонтальный скролл **внутри** контейнера
  (`overflow-x: auto`), никогда не вся страница.
- Кнопки: минимум 44×44 px; primary — на всю ширину, если это главное действие.

## 4. Компоненты

### 4.1. Кнопки

| Вариант | Использование | Состояния |
|---------|---------------|-----------|
| Primary | главное действие экрана | default, hover, active, focus, disabled, loading |
| Secondary | альтернативное действие | то же |
| Ghost | «Отмена», «Детали», ссылки-кнопки | то же |
| Danger | удаление, destructive | default, hover, focus, disabled |
| Link | навигация внутри текста | default, hover, focus, visited |

Требования:

- Высота 36 px (compact) / 44 px (mobile/primary).
- Иконка + текст; иконка без текста только с `aria-label` и tooltip.
- Loading: спиннер + текст «Сохраняю…», кнопка disabled, размер не скачет.
- Не более одной primary на экран/секцию.

### 4.2. Поля формы

- Label всегда видим, связан `for`/`id`; placeholder — только подсказка.
- Help text под полем, error text — danger + иконка.
- Обязательные поля: явная пометка (не только `*`).
- Ошибка — у поля, не только сверху.
- Селекты — нативные, если нет причины иначе.
- Чекбоксы/радио — label кликабелен, зона ≥ 44 px.
- Никаких `input` без label (сейчас 51 из 58 в редакторе).

### 4.3. Табы

- Кнопки `<button role="tab">` или ссылки с `role="tab"`.
- `aria-selected`, `aria-controls`, `tabindex`, клавиши ←/→/Home/End.
- Активный таб: подчёркивание/фон + текст, не только цвет.
- На mobile — горизонтальный скролл с fade-индикатором.

### 4.4. Карточки

- Surface, border, radius 12, padding 16–24.
- Заголовок, meta, тело, действия.
- Hover — только если карточка кликабельна.
- Варианты: lecture card, video discovery card, status card, metric card.

### 4.5. Таблицы

- Заголовок sticky при длинном списке.
- Числа выровнены вправо, текст — влево.
- На mobile: `data-label` карточки или горизонтальный скролл в контейнере.
- Не более 6–8 колонок на первом уровне; остальное — «Детали».
- Сортировка — явная, с `aria-sort`.

### 4.6. Статусы

Статус = **иконка + текст + цвет** (не только цвет). Компонент `status-badge`:

| Тон | Примеры |
|-----|---------|
| neutral | «В очереди», «Отменено», «Пропущено» |
| info | «Скачивание», «Распознавание речи», «Перевод» |
| success | «Готово» |
| warning | «Готово частично», «Прервано», «Нужно пересчитать» |
| danger | «Ошибка» |

Правило: технические enum'ы не показывать пользователю. Полный маппинг —
в `03-user-flows.md`, раздел 2.2. Технические `PENDING/COMPLETED` этапов —
только в «Детали».

### 4.7. Прогресс

- `<progress>` или div с `role="progressbar"`, `aria-valuemin/max/now`,
  `aria-label`.
- Детерминированный: стадия + «3 из 10» + %.
- Неопределённый: анимированная полоса + текст «Обрабатываю…».
- Для скачивания — отдельная строка: %, МБ, скорость, ETA.
- Не показывать 100%, пока статус не терминальный.

### 4.8. Уведомления

| Тип | Где | Поведение |
|-----|-----|-----------|
| Inline alert | над секцией/формой | остаётся до действия |
| Toast | после успешного сохранения/экспорта | 5–7 с, закрывается, `aria-live=polite` |
| Error banner | критическая ошибка страницы | не auto-hide, содержит действие |
| Field error | у поля | до исправления |

- Цвет + иконка + заголовок; текст без «Что-то пошло не так».
- Технические детали — `<details>`.

### 4.9. Модальные окна / drawers

- Для подтверждения удаления, выбора опций импорта, просмотра diff.
- `role="dialog"`, `aria-modal`, focus trap, Esc, возврат фокуса.
- На mobile — bottom sheet.
- Не использовать для длинных форм (мастер импорта — страница/секция, не
  модалка на 20 полей).

### 4.10. Пустые состояния

Обязательные элементы:

1. Заголовок (что здесь будет).
2. Одно предложение пользы.
3. Одно primary-действие.
4. Вторичная ссылка (например, «Как это работает»).

Примеры: «Пока нет лекций» → «Добавьте первое видео, и здесь появятся
конспекты» + «Добавить материал». Не оставлять голую строку в таблице.

### 4.11. Скелетоны и загрузка

- Для HTMX-обновлений — skeleton/placeholder с фиксированной высотой.
- Не заменять весь экран спиннером, если обновляется только секция.
- Кнопки — в loading, не исчезают.

### 4.12. Diff / код

- Моноширинный шрифт, `+`/`−`, цвет + префикс.
- Горизонтальный скролл внутри блока.
- Для File Agent — подсветка синтаксиса не обязательна в первой версии.

## 5. Адаптивность

| Брейкпоинт | Поведение |
|------------|-----------|
| `< 640` | одна колонка, drawer, карточки вместо таблиц, primary на всю ширину |
| `640–1023` | drawer, 2 колонки карточек, таблицы со скроллом |
| `1024–1279` | sidebar 64–240, контент 1–2 колонки |
| `≥ 1280` | sidebar 240, контент 1200–1280 |

Правила:

- `<meta name="viewport" content="width=device-width, initial-scale=1">` на
  всех страницах (сейчас отсутствует).
- Никаких фиксированных `min-width` у основных контейнеров.
- `overflow-wrap: anywhere` для длинных имён файлов/URL.
- Медиа (слайды) — `max-width: 100%`, `height: auto`.
- Тест на 390, 768, 1024, 1440.

## 6. Доступность

Цель — WCAG 2.1 AA (без формальной сертификации).

1. **Контраст:** текст ≥ 4.5:1, крупный ≥ 3:1, UI-границы ≥ 3:1.
2. **Focus:** видимый `:focus-visible` ring 2 px, не убирать outline без
   замены.
3. **Клавиатура:** все действия доступны с Tab/Enter/Space/Esc; табы, меню,
   модалки — с корректными ARIA-паттернами.
4. **Подписи:** у каждого поля label; иконки-кнопки — `aria-label`.
5. **Статусы:** не только цвет; текст + иконка.
6. **Динамика:** `aria-live="polite"` для статуса/ответов/тостов; не
   перезагружать страницу каждые 4 с.
7. **Структура:** один `h1`, иерархия заголовков, `<main>`, `<nav>`,
   skip-link.
8. **Язык:** `<html lang="ru">`; технические термины — с пояснением.
9. **Формы:** ошибки связаны с полем (`aria-describedby`), автофокус — только
   в диалогах.
10. **Движение:** уважать `prefers-reduced-motion`.
11. **Размер:** touch-target ≥ 44×44 px.
12. **Тексты:** понятные, без «Произошла ошибка» без причины.

## 7. Тёмная тема

**Рекомендация:** в первом рефакторинге не делать полноценную тёмную тему.
Причины:

- текущий UI не имеет токенов, контрастных пар и тестов;
- тёмная тема требует проверки всех статусов, diff, слайдов, таблиц;
- приоритет — основной сценарий и мобильная адаптация.

Что сделать сейчас: ввести токены и не хардкодить цвета в шаблонах. Тогда
тёмная тема добавляется отдельным этапом через `[data-theme="dark"]` и
`prefers-color-scheme`, без переписывания компонентов. Оценка — после
стабилизации светлой темы.

## 8. Контент и терминология

### Правила

- Интерфейс — по-русски; технические термины — только там, где они нужны
  администратору.
- Статусы — человеческие слова, не enum.
- Время: «2 мин назад», «18 окт 2026, 14:32»; не ISO с наносекундами.
- Длительность: «12:34», не «754000 мс».
- Размер: «5,6 МБ».
- Ошибки: причина + действие + (в деталях) техническая строка.
- Кнопки: глагол + объект («Скачать конспект», «Повторить обработку»).
- Не использовать «Обработать заново» и «Возобновить» одновременно.

### Словарь

| Технически | Пользователю |
|------------|--------------|
| `COMPLETED` | Готово |
| `PARTIAL` | Готово частично |
| `FAILED` | Ошибка |
| `TRANSCRIPTION` | Распознавание речи |
| `TEXT_PROCESSING` | Составление конспекта |
| `RAG_INDEXING` | Подготовка поиска по лекции |
| `SLIDE_EXTRACTION` | Извлечение слайдов |
| `EXPORT` | Сохранение документов |
| `grounded` | Подтверждено источниками |
| `tokens` | Токены (только advanced) |
| `embedding` | Векторное представление (только advanced) |
| `MCP` | Инструменты ассистента / API (только admin) |
| `provider/model` | Провайдер/модель (только advanced/admin) |

## 10. Критерии приёмки дизайн-системы

- Один `app.css` (или набор из 3–4 файлов) вместо 14 inline `<style>`
  (Support Assistant в UX-2 намеренно не мигрируется).
- Все страницы используют общий layout и навигацию.
- Нет горизонтального скролла на 390 px (кроме намеренных таблиц/кода
  внутри контейнера).
- Все интерактивные элементы доступны с клавиатуры и имеют focus-state.
- Все поля имеют label; все статусы — текст + иконка/тон.
- Компоненты переиспользуются минимум на 3 страницах.
- Playwright может найти элементы по роли/тексту без `data-testid` (но
  `data-testid` допускается для нестабильных областей).
