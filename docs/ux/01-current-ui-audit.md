# UX-1. Аудит текущего интерфейса Lecture Processor

Дата аудита: 2026-10-18
Ветка: `fix/runtime-stabilization`
HEAD на момент аудита: `f57b10c` (`fix: stabilize YouTube import with unified yt-dlp options`)

Документ фиксирует **фактическое состояние интерфейса**, а не только заявленное
в README. Все выводы ниже проверены по исходникам; ключевые состояния проверены
в браузере (Chromium через Playwright). Изменения кода не вносились.

## 1. Методика и среда аудита

1. Прочитаны `README.md`, `AGENTS.md`, веб-контроллеры, Thymeleaf-шаблоны,
   фрагменты, JS/CSS и сервисы, формирующие модели страниц.
2. Приложение запущено на изолированном порту **18095** с копией тестовой базы
   (`target/e2e-week8c` → `target/ux-audit-storage`), чтобы не изменять
   пользовательские данные, SQLite, видео и результаты обработки.
3. Второй экземпляр запущен на порту **18096** с пустой базой для проверки
   пустых состояний.
4. Проверены desktop (1440×1000) и mobile (390×844) для 16 маршрутов.
5. Для проверки ошибки обработки загружен короткий fixture
   `demos/fixtures/sample-lecture-ru.mp4`. В аудите не были заданы `FFMPEG_PATH`
   / `FFPROBE_PATH`, поэтому пайплайн реально остановился на `MEDIA_VALIDATION`
   с ошибкой `ffprobe`. Это дало настоящее состояние `FAILED`, а не имитацию.
6. Тяжёлые LLM/Whisper-операции не запускались. Ответы ассистентов, Code Review
   и File Agent проверялись только по коду/пустым состояниям, без платных или
   длительных вызовов.

Артефакты аудита (не коммитятся, лежат в `target/`):

- `target/ux-audit-app.log`, `target/ux-audit-empty.log`
- `target/ux-audit-browser.json` (метрики 32 прогонов страниц)
- `target/ux-audit-shots/*.png` (скриншоты desktop/mobile)
- `target/ux-audit-storage/` (копия тестовой БД и артефактов)

## 2. Краткая сводка

Текущий интерфейс — это **набор отдельных Thymeleaf-страниц с локальными
inline-стилями**, без общего layout, глобальной навигации, дизайн-системы и
адаптивной вёрстки. Каждая страница решает свою задачу, но пользователь не
видит единого продукта:

- главная одновременно является формой импорта, формой URL-импорта и таблицей
  библиотеки;
- из главной нельзя попасть в Support, Code Review и File Agent — эти разделы
  доступны только по прямым ссылкам с других технических страниц;
- у одной лекции две кнопки («Обработать заново» и «Возобновить»), которые
  вызывают один и тот же backend-метод;
- статус `COMPLETED` может отображаться рядом с `PENDING`-этапами, прогрессом
  `60%` и подписью «Этап: Экспорт документов (10/10)»;
- на мобильном экране 10 из 16 проверенных страниц имеют горизонтальный скролл
  (до 1097 px при viewport 390 px);
- в шаблонах нет `<meta name="viewport">` и ни одного `@media`;
- в CSS нет общих файлов: 15 шаблонов содержат собственный `<style>`;
- HTMX подключается с `unpkg.com`; при недоступности CDN интерактивные
  сценарии (обновление статуса, чат, ассистенты) не работают;
- в интерфейсе массово отображаются внутренние enum'ы, технические метрики и
  англоязычные термины (`COMPLETED`, `PENDING`, `MCP`, `grounded`, `tokens`,
  `embedding`, `RAG`, `LLM`, `DOCX`, `cloud`).

При этом backend и HTMX-контракты уже дают достаточно данных для понятного
интерфейса: прогресс по стадиям, ошибки, предупреждения, ревизии, варианты
экспорта, citations и tool trace. Проблема в основном **представление**, а не
в отсутствии функциональности.

### 4.3. Ошибки, частичная обработка и повторный запуск

- **Ошибка скачивания YouTube.** В `/discover` после ошибки импорта показывается
  сообщение и ссылки «Открыть видео на исходной платформе» / «загрузить
  локальный файл» — это хороший паттерн, но он есть только на `/discover`,
  не на главной и не в карточке.
- **Ошибка LLM / недоступная Ollama.** Карточка показывает сырой `errorMessage`
  и `warnings`; ссылки на `/diagnostics` и на повтор только упавшей стадии нет.
- **PARTIAL.** Статус `PARTIAL` — терминальный, но UI не объясняет, что именно
  не выполнено и какие документы доступны. Нет отдельного визуального состояния.
- **Повторный запуск.** «Обработать заново» и «Возобновить» вызывают один и тот
  же `jobService.submit(id)` (`LectureWebController`, методы `process` и `resume`).
  Пользователь выбирает между двумя неотличимыми действиями.
- **INTERRUPTED после рестарта.** Пользователь видит новый enum и кнопку
  «Возобновить» без объяснения, что дорогие этапы не будут повторены.
- **Удаление.** Форма `POST /lectures/{id}/delete` не имеет подтверждения и
  расположена рядом с «Отменить». Случайное удаление необратимо.

## 5. Каталог UX-проблем

Приоритет: **P0** — блокирует основной сценарий; **P1** — заметно мешает;
**P2** — улучшение.

### P0-1. Нет общей навигации и информационной архитектуры

Каждая страница содержит свой набор ссылок «← К лекциям» / «Настройки» /
«Ассистент». Support, Code Review и File Agent не достижимы с главной.
Пользователь не понимает, где находится и куда идти дальше.

Подтверждение: 15 шаблонов, 15 разных наборов ссылок; в `index.html` ссылки
только в подвале, в `lecture.html` — только «← К списку» и две ссылки.

### P0-3. Противоречивый и технический статус обработки

На реальной лекции одновременно отображаются:

- `Статус: COMPLETED`;
- `Этап: Экспорт документов (10/10)`;
- прогресс `60%`;
- `Разрешение источника … Экспорт документов` — часть `COMPLETED`, часть `PENDING`;
- `Скачивание: FINISHED · 100%`.

Пользователь не может понять, готова ли лекция. Статусы — сырые enum'ы
(`JobStatus`, `JobState`, `StageState`) и не сопровождаются объяснением.
`PARTIAL` и `INTERRUPTED` не имеют отдельного представления.

Подтверждение: `fragments/status.html:8-18`, `pipeline/JobStatusService`,
`domain/JobStatus`, `pipeline/StageState`.

### P0-4. Дублирующиеся действия и конкурирующие кнопки

- «Обработать заново» и «Возобновить» → `/process` и `/resume` →
  один `jobService.submit` (`LectureWebController.java`, методы `process/resume`).
- На главной две формы URL: «Проверить» и «Скачать и обработать» —
  два поля ввода и два пути импорта.
- Discovery импортирует видео своей формой (с `clean`/`slides`), главная —
  своей (с quality/audioOnly/clean/slides/языком/переводом).
- В редакторе экспорт доступен кнопками `Original/Russian/Bilingual/Notes DOCX`
  и одновременно ссылками «скачать» в блоке состояния; на карточке — ещё
  4 ссылки на DOCX.
- Support: «Новое обращение» и «Свободный вопрос» создают тикет двумя путями.

### P0-5. Нет понятного восстановления после ошибки

Реальное состояние `FAILED` после загрузки fixture:

```
Статус: FAILED
Этап: Проверка медиа (3/10)
Ошибка: Не удалось запустить процесс: ffprobe
```

На этой же странице:

- 10 ссылок «Скачать» (JSON/Markdown/DOCX), все отдают 404;
- «Обработать заново», «Возобновить», «Отменить» — одновременно;
- нет ссылки на `/diagnostics`, нет подсказки «установите FFmpeg/FFprobe»,
  нет кнопки «повторить с этой стадии».

### P1-6. Главная перегружена и не является рабочей панелью

Первый экран — три конкурирующих блока и таблица. Нет:

- активных задач и прогресса;
- «продолжить последнюю»;
- «требует внимания»;
- пустого onboarding-состояния (только строка «Пока нет лекций»);
- быстрых действий с результатами.

### P1-7. Библиотека — это техническая таблица

Колонки: `Лекция`, `Язык`, `Статус`, `Перевод`, `Создано`, действия.
Название — `originalFilename` или тема; дата — ISO с наносекундами
(`2026-10-17T23:31:57.792098700Z`); статус — enum; нет превью, платформы,
длительности, доступных документов. Фильтр языка — свободный ввод `en / ru`.
Нет пагинации/виртуализации, хотя список рендерится целиком.

### P1-8. Редактор небезопасен для пользователя

- 5 табов — `div` без `role`, `tabindex`, клавиатурной навигации.
  Проверено: `tagName=DIV`, `role=null`, `tabindex=null`.
- 51 из 58 `input/select/textarea` не имеют label/aria-label.
- Нет индикатора несохранённых изменений: правка textarea не меняет UI,
  кнопка сохранения всегда активна.
- Нет `beforeunload`: после правки и перезагрузки изменения теряются
  (проверено в браузере).
- Конфликт версий (`409`) показывается как ошибка, без сравнения/перезагрузки.
- После экспорта сообщение содержит имя артефакта текстом, а не ссылкой.
- История: подписи «От»/«До» и кнопка «Восстановить „До“» неоднозначны.
- Для длинных лекций (746 сегментов в предыдущем E2E) страница рендерит
  все textarea сразу — риск тяжёлого DOM.

### P1-9. Discovery выглядит как отладочный инструмент

- 21 результат, 21 форма «Добавить в библиотеку» с чекбоксами `очистка`/`слайды`.
- Технические подписи `EMBEDDING_TOPIC_PROFILE`, `TITLE_DESCRIPTION`,
  `RUTUBE_PUBLIC_API`, `YT_DLP_SEARCH`.
- Релевантность `90%` у нерелевантных русских видео; нет объяснения,
  что это оценка по названию/описанию, а не по содержанию.
- Нет превью/карточек, нет пустого состояния, нет явного «почему не нашлось».
- Провайдеры показаны отдельной таблицей с method/ограничением.

### P1-10. Настройки перегружены и содержат недостоверные подписи

- 29 форм, 5 400+ символов, без вкладок.
- `Ollama (local) — cloud`: при `cloud=false` шаблон показывает `cloud`
  (`settings.html:47`; вероятно, ошибка выражения Thymeleaf). Это противоречит
  сообщению о приватности и путает, уходит ли текст в облако.
- «Day 32 подготовка: … Сам reviewer ещё не реализован» (`settings.html:173`)
  устарело: Code Review реализован.
- Нет danger zone; удаление DeepSeek-ключа подтверждается, удаление
  YouTube/VK-ключа и терминов глоссария — нет.
- Нет разделения «базовые» и «расширенные» параметры; `temperature`,
  `maxTokens`, `contextWindow`, `thinking`, `prompt template` показаны всем.

### P1-11. Обратная связь и защита от опасных действий непоследовательны

- Flash-сообщения только сверху, без автоскрытия на большинстве страниц.
- Нет per-row busy-state; кнопки не блокируются на время запроса.
- Удаление лекции и терминов глоссария — без подтверждения.
- `GET /support/lecture/{id}` создаёт/находит тикет — GET меняет состояние.
- File Agent перезагружает всю страницу каждые 4 с (`meta refresh`), теряя
  позицию и введённый текст.

### P2-12. Доступность

- Один `<label for>` на всё приложение (`settings-login.html`).
- Табы редактора недоступны с клавиатуры.
- Нет `aria-live` у обновляемого статуса/ответов.
- Статусы в основном цвет + текст, но цветовые классы не сопровождаются
  иконкой/паттерном.
- Нет skip-link, `main`, `nav`; заголовки прыгают (`h1` → `h3` на главной,
  support/file-agent).
- Мелкий шрифт `0.75–0.85rem` в админ-таблицах.
- Favicon отсутствует (`/favicon.ico` → 404), это даёт console error.

### P2-13. Технические ограничения платформы

- Нет `static/`: CSS/JS не кэшируются и дублируются.
- HTMX только с CDN. При блокировке `unpkg.com` `window.htmx === undefined`
  (проверено), интерактивность теряется. Для локального/homelab-приложения
  это существенный риск.
- Три разных механизма обновления: HTMX `every 3s/5s`, `meta refresh 4s`,
  обычный GET-поиск.
- `jsessionid` попадает в URL после редиректа при первом запросе
  (`/lectures/{id};jsessionid=…`) — некрасиво и нежелательно для ссылок.
- Ошибки внешних процессов показываются как есть (`ffprobe`, `yt-dlp stderr`),
  без маппинга в пользовательский язык.
- `schema.sql`/данные не затрагивались; аудит проводился на копии.

## 7. Технические ограничения для будущего рефакторинга

1. **Backend-контракты менять нельзя.** Все данные для нового UI уже есть в
   моделях контроллеров; для некоторых улучшений (глобальный список задач,
   точная доступность артефактов) потребуются только additive view-модели,
   а не изменение API.
2. **Thymeleaf без layout-диалекта.** Нужен свой `fragments/layout.html` на
   `th:replace`/`th:fragment`; новую зависимость не добавлять.
3. **HTMX 1.9.12 уже используется.** Достаточно перенести файл в
   `static/vendor/` и подключить локально; сценарии не менять.
4. **CSRF-модель неоднородна.** `/settings`, `/api/providers`, `/code-review`,
   `/file-agent`, `/diagnostics` защищены `AdminSecurityFilter`; лекции,
   discovery и support используют собственные проверки/токены. При рефакторинге
   нельзя «унифицировать» это без отдельного security-задания.
5. **Статусы — три модели.** `JobStatus` (жизненный цикл лекции), `JobState`
   (job), `StageState` (этап). UI должен отображать одну человеческую модель,
   а технические детали прятать в «Детали».
6. **Данные пишутся в SQLite и файлы.** Любые E2E-проверки — только на
   отдельном `LECTURE_STORAGE_ROOT`.
7. **`docs/` и `AGENTS.md` намеренно в `.gitignore`.** UX-документы остаются
   локальными; это не ошибка и не повод делать `git add -f`.
